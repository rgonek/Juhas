# Community review mods compared with Juhas

Research date: 2026-11-03. Source inspection only: the remote repositories were cloned into a unique temporary directory, pinned below, and read without installation or execution. This is not a latency benchmark or native compatibility test. The local comparison includes the current Juhas working tree and the proposed [agent review / refresh design](agent-review-refresh-design.md); proposed features are not described as implemented.

This report starts with the three closest additional review tools discovered through the Herdr community catalog. The earlier [Git comparison](git-operations-comparison.md) covers Branch Review and Herdr Annotator separately.

## Catalog coverage and evidence boundary

**Subsequent user decision:** include the remaining useful proposals in the [design](agent-review-refresh-design.md), but **exclude two-way threads and agent reply/resolve ingestion**. The source comparisons below retain those capabilities as competitor facts; they do not authorize implementing them in Juhas. Checkpoints of uncommitted work, optional multibuffer, bounded prefetch, reading improvements and optional guided reading are now staged design scope rather than merely unselected candidates. Implementation has not started.

The [Herdr Mods page](https://herdr.dev/mods/) loads community items from its public [catalog index](https://assets.herdr.dev/mods/index.json). The index checked on 2026-11-03 contained **258 entries**, with `generatedAt` of `2026-11-03T12:30:16` (rendered as a date by PowerShell). The initial HTML's Community 0 is a pre-fetch placeholder, not evidence of an empty catalog. Names and descriptions were screened across the index; selected implementations were then read at pinned revisions. This is not an audit of every mod's code.

Core comparisons below cover Commit review, reviewer, Agent review, Tabbed Changes, Git Changes, Better Changes and WASM diff. Additional source readings cover Walkthrough, Plannotator, Diff (session-diff), Spend and the entry point of Reviews / Herdr Ranch. The previous comparison covers Branch Review and Herdr Annotator. VCS and Changes Plus were screened at README/recipe depth, clearly marked below. PR listings, GitHub/GitLab/Jira hubs, Git Graph/Flow/Dash, worktree launchers, Ship it and agent dashboards are adjacent tools; their catalog presence is not evidence that Juhas needs their repository-management controls.

### Clarification following the user's syntax-coloring observation

The user's installed mod and checkout have identical `ui.js` content (SHA-256 `C21075E30C3F50F6739A332FBBBAF8D3603E4598F789D02EF6B1C1608C8E3CAA`, checked read-only). ## Commit review: the most relevant additional comparison

**Confirmed competitor capability, explicitly excluded from Juhas: two-way review threads.** The panel stores human comments as pending, supports replies, resolve/reopen and notifications for new published agent comments. Its `herdr-review` CLI lets an agent list/show threads, reply, resolve and create findings. The generated review message includes explicit instructions for replying to a thread by its ID. This is actual code, not just a README promise. Juhas currently delivers one message and keeps delivery history, but it has no corresponding reply/resolve ingestion channel. Sources: [store API](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/store.js#L41-L74), [agent feedback protocol](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/agent.js#L22-L39), [CLI reply/resolve/publish](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/herdr-review/herdr-review.py#L329-L414).

This would help a multi-round human/agent workflow: the person can see which remark the agent says it addressed and what changed, instead of finding the answer in a terminal transcript. It is a separate subsystem, not a small UI checkbox. If added to Juhas, keep agent-reported resolution distinct from human verification, validate repository/source/thread identities on ingestion and preserve uncertain-delivery behavior. Do not silently infer that a successful Send means the issue was fixed.

**Viewed progress is content-aware.** Commit review keys a committed file by commit SHA/path. For whole-branch review it saves the old/new blob pair and distinguishes unviewed, viewed and changed-since-viewed. Marking the current file Viewed advances to the next unviewed file. This strongly supports the file-progress addition already proposed for Juhas. Juhas should also include modes/type/rename semantics when fingerprinting a file: unchanged blob IDs alone do not capture a mode-only change. Sources: [blob metadata](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/git.js#L96-L119), [Viewed and navigation](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/main.js#L478-L503).

**Useful rendering detail:** it compares fetched lines to the currently displayed lines and avoids reparsing/tokenizing unchanged data. That is beneficial independently of Git process caching. Juhas should retain immutable patch/token rows and skip notifications/rebuilds for unchanged refresh candidates. Source: [unchanged diff fast path](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/main.js#L301-L318).

**Git efficiency is not uniformly better.** A full refresh repeats repository lookup, branch enumeration, current branch, base discovery, branch tip, merge-base, history, changed-file metadata for every selected review unit, and the selected patch. The timer calls this every 10 seconds. There is a loading/coalescing guard and generation check, but no visible-pane gating in this path and no immutable cross-refresh diff cache. File lists for multiple selected commits run concurrently, which reduces waiting opportunities but not the number of Git processes. Sources: [timer and full refresh](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/main.js#L119-L244), [Git command implementations](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/git.js#L28-L129).

Thread/viewed changes take a smaller path: a local store watcher reloads threads and Viewed data without reloading the Git diff. Remote stores rely on the timer. This separation is worth borrowing for any future Juhas reply channel. However each store invocation launches `herdr-review`, whose Python store resolves Git's common directory, so one helper request must not be counted as zero Git work. Sources: [store-only refresh](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/main.js#L247-L278), [store location](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/herdr-review/herdr-review.py#L64-L94).

**Source anchoring is a tradeoff, not a template to copy.** Branch display can show threads originally made on its commits. Placement finds the first quoted line on the requested side, choosing the nearest matching line number, then extends by the stored range length. This is convenient, but repeated source text can place a thread ambiguously. Juhas currently keeps comments at their exact comparison rather than silently relocating them. A future cross-view thread overlay should remain explicitly sourced and show unplaced/outdated feedback instead of guessing. Sources: [cross-view thread inclusion](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/main.js#L331-L359), [placement algorithm](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/diff.js#L51-L75).

**Compatibility caution:** its helper imports `fcntl` and uses `flock`; this is not a directly usable native Windows helper. Its scope construction covers committed work, not the combined dirty/untracked review required here. These facts rule out copying its runtime wholesale. Sources: [locking](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/herdr-review/herdr-review.py#L30-L94), [committed comparison units](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/main.js#L195-L217).

## reviewer: readable code and lightweight local comments

**Confirmed gap: syntax coloring.** Both reviewer and Commit review tokenize diff rows once when source changes and render token spans. Juhas currently colors added/removed lines as a whole; it does not tokenize syntax in either Unified or Split. Adding bounded, cached, theme-aware syntax coloring is a directly useful improvement for reading agent changes. Unknown languages should remain plain text, and the tokenizer must not change original text/anchors. Sources: [reviewer tokenizer and diff rows](https://github.com/vytasgavelis/herdr-reviewer/blob/424ca3e9cbe3e739df12e356a250c72612477fb5/mods/reviewer/main.js#L315-L322), [Commit review row tokenization](https://github.com/Mantiq-com/herdr-commit-review/blob/9c62ecb73b75d6651806f7c3168e63fba3adcece/mods/commit-review/diff.js#L8-L35), [local Juhas renderer](../mods/juhas/ui.js).

reviewer combines a base-to-working-tree branch scope, untracked files and an empty-repository fallback; its last-commit mode includes dirty changes too. These reinforce the already identified aggregate-plus-dirty and initial-uncommitted requirements rather than introducing another necessary mode. Its comments are local shared-state data, so Add immediately stores the note and closes the composer without a Git query. The saving pattern is responsive, but its source identity is a repository/scope and captured line descriptors rather than Juhas's exact immutable comparison. Sources: [scope/file reads](https://github.com/vytasgavelis/herdr-reviewer/blob/424ca3e9cbe3e739df12e356a250c72612477fb5/mods/reviewer/main.js#L150-L197), [comment storage/save](https://github.com/vytasgavelis/herdr-reviewer/blob/424ca3e9cbe3e739df12e356a250c72612477fb5/mods/reviewer/main.js#L425-L444).

Its refresh combines a 10-second timer with a local folder watcher. It re-reads status, HEAD, base/scope metadata, file statistics and the current patch; an unchanged-line fast path avoids repeated syntax work. There is no visible-pane gating in the timer path. This is not a reason to replace Juhas's intended incremental, visible-only refresh with repeated full reads. Sources: [timer/watcher](https://github.com/vytasgavelis/herdr-reviewer/blob/424ca3e9cbe3e739df12e356a250c72612477fb5/mods/reviewer/main.js#L103-L134), [refresh queries](https://github.com/vytasgavelis/herdr-reviewer/blob/424ca3e9cbe3e739df12e356a250c72612477fb5/mods/reviewer/main.js#L136-L223), [patch and fast path](https://github.com/vytasgavelis/herdr-reviewer/blob/424ca3e9cbe3e739df12e356a250c72612477fb5/mods/reviewer/main.js#L294-L322).

It also supports asking an agent about selected code and retaining normal stage/commit controls from the Changes panel. Asking about code is optional adjacent convenience. Staging, committing and destructive Git operations should not be imported into Juhas's focused human-review interface merely for feature parity.

## Agent review: working snapshots and event-driven updates

Its baseline can be an actual saved working-tree snapshot, not only a commit. Mark seen records the current tree, so the next round can show only later changes even if neither round was committed. This is a meaningful capability beyond Juhas's current committed checkpoints and is a good later candidate if the user frequently iterates before committing. Sources: [baseline/load/Mark seen](https://github.com/jkuepker/herdr-mods/blob/a3130a3271297a810a31504a818fbce42b7b009b/agent-review/mods/agent-review/main.js#L88-L171), [snapshot implementation](https://github.com/jkuepker/herdr-mods/blob/a3130a3271297a810a31504a818fbce42b7b009b/agent-review/mods/agent-review/review.js#L26-L48).

Its implementation uses an alternate index, `git add -A` and `git write-tree` to create immutable trees without updating the user's real index. It does write Git objects. It then reads one whole diff between trees rather than lazy per-file patches. These snapshots and old trees need lifecycle/GC handling. The code relies on `sh` and local `mkdir -p`; it is not a native Windows snapshot implementation to transplant. Juhas should not silently introduce Git-object writes on every 15-second poll. Source: [Git snapshot, initial baseline and full diff](https://github.com/jkuepker/herdr-mods/blob/a3130a3271297a810a31504a818fbce42b7b009b/agent-review/mods/agent-review/review.js#L26-L68).

It intentionally does not poll snapshots on a timer. It reloads on open, selected agent change, explicit reload, Mark seen, revert, and when a picked agent transitions out of working. The event is a useful optional trigger alongside the requested 15-second check, provided it is coalesced rather than performing two identical refreshes. Source: [load policy](https://github.com/jkuepker/herdr-mods/blob/a3130a3271297a810a31504a818fbce42b7b009b/agent-review/mods/agent-review/main.js#L88-L110), [agent-status trigger](https://github.com/jkuepker/herdr-mods/blob/a3130a3271297a810a31504a818fbce42b7b009b/agent-review/mods/agent-review/main.js#L341-L348).

The panel warns when multiple agents share a repository and does not attribute those shared lines to one agent. Juhas should preserve that distinction when selecting a delivery recipient: a recipient is not proof of change authorship. Its separate Paste/Send and hunk revert features are not required for the user's batch-feedback workflow; Juhas already provides edited preview, Copy and explicit Send. Source: [shared-checkout warning](https://github.com/jkuepker/herdr-mods/blob/a3130a3271297a810a31504a818fbce42b7b009b/agent-review/mods/agent-review/main.js#L349-L387).

## Recommendations from these three mods

| Candidate | Priority / disposition | Relationship to accepted Juhas design |
|---|---|---|
| Cached syntax coloring in both diff layouts | High-value addition | New concrete gap; preserve plain-text fallback, text/anchor identity and rendering limits |
| Viewed / changed since viewed / next unviewed | Keep planned work | Strong source-backed validation; include full content and change semantics |
| Skip reparsing/tokenization/notify for unchanged source | Include with performance work | Already consistent with stable incremental publication |
| Two-way threads, agent replies and reopen/resolve | Excluded by the user | Competitor capability only; do not add a reply/resolve interface to Juhas |
| Baseline from an uncommitted snapshot | Later candidate | Extends checkpoints for pre-commit iteration; requires explicit storage/write/GC design |
| Refresh on agent finishing | Optional extra trigger | Coalesce with the required 15-second visible-only loop |
| Show original-source comments in aggregate views | Optional, correctness-sensitive | Never silently move feedback based on nearest matching text |
| Agent picker/multi-repository dashboard | Do not broaden by default | Current active-project context already matches the user |
| Stage, commit, revert, checkout, merge controls | Exclude from focused review scope | Agents handle changes; review UI should stay small |

None of these three review mods establishes the complete refresh contract the user requested: visible-only, unchanged pinned commit/file/diff, no blanking, no UI lock, stable unsaved input and rejection of late results. Preserve that contract even if a competitor has more controls or a shorter polling interval.

### Tabbed Changes

Useful implemented capabilities: a reusable preview diff tab (single click), pinned separate tabs (double click), and an all-files multibuffer with collapsible per-file headers. Diff layout toggles reuse already-loaded text. It also provides plain file tabs and opening the corresponding source line in a configured external terminal editor. [Tab reuse and pinning](https://github.com/sangit0/herdr-tabbed-changes/blob/76efbdec9827aeea2c49008b4d1c59b1d2cfbf72/mods/tabbed-changes/tabs.js#L26-L59), [all-files fetching and row building](https://github.com/sangit0/herdr-tabbed-changes/blob/76efbdec9827aeea2c49008b4d1c59b1d2cfbf72/mods/tabbed-changes/diff.js#L106-L152).

The multibuffer reads one tracked-file diff for the whole HEAD-to-working-tree comparison rather than one Git process per file, then enumerates untracked names and reads up to 40 new files directly. It caps displayed rows at 8000, after collecting command output. It does not implement review comments/source anchoring; whole-diff fetching should not replace Juhas's lazy one-file path unconditionally. Optional bounded prefetch is a reasonable experiment when someone actually visits many small files.

Syntax coloring exists in a small line tokenizer, used while creating row elements; this is materially more readable than Juhas's current plain code text, but the grammar is deliberately simple, not full semantic highlighting. [Tokenizer](https://github.com/sangit0/herdr-tabbed-changes/blob/76efbdec9827aeea2c49008b4d1c59b1d2cfbf72/mods/tabbed-changes/highlight.js#L1-L49), [token rendering](https://github.com/sangit0/herdr-tabbed-changes/blob/76efbdec9827aeea2c49008b4d1c59b1d2cfbf72/mods/tabbed-changes/ui.js#L30-L35).

Efficiency/refresh limits: 10-second timers run in panel and diff-view instances, plus a local `watchFolder` loop. There is an in-flight guard with one coalesced follow-up and a selection signature that rejects stale diff responses. A quiet reload of the same selection leaves rows visible until replacement. There is no visible-only gate in these paths, and immutable diff caching is absent. Panel refresh does root resolution, status, HEAD, staged numstat and unstaged numstat sequentially. [Panel refresh](https://github.com/sangit0/herdr-tabbed-changes/blob/76efbdec9827aeea2c49008b4d1c59b1d2cfbf72/mods/tabbed-changes/panel.js#L35-L95), [diff scheduling and publication](https://github.com/sangit0/herdr-tabbed-changes/blob/76efbdec9827aeea2c49008b4d1c59b1d2cfbf72/mods/tabbed-changes/diff.js#L20-L81).

### Git Changes

A useful command reduction: `status --porcelain=v2 --branch -z` supplies branch OID and status together, so panel refresh does not need a separate HEAD-existence query. Independent statistics/stash/remote/last-commit requests run with `Promise.all`; history is loaded only when its history section is selected. This reduces unnecessary history work, not total costs of all features. [Status argv and parser](https://github.com/aBER0724/herdr-git-changes/blob/7a164bf9c20555a105c0df0a6841b4608ccdd237/mods/git-changes/git.js#L13-L57), [refresh and conditional history](https://github.com/aBER0724/herdr-git-changes/blob/7a164bf9c20555a105c0df0a6841b4608ccdd237/mods/git-changes/panel.js#L90-L129).

It coalesces refreshes, rejects changed-context publication and reuses one diff tab per space, including an opening-in-progress guard to prevent duplicate tabs. The diff reader preserves rows on ordinary background reload and rejects superseded picks. However its 10-second diff timer also reloads committed diffs; only its watcher skips commit reload. Each diff refresh queries HEAD existence before reading the selected patch. No immutable OID cache or visibility gate appears in that path. [Reusable tab](https://github.com/aBER0724/herdr-git-changes/blob/7a164bf9c20555a105c0df0a6841b4608ccdd237/mods/git-changes/diff.js#L60-L74), [diff reload/timers](https://github.com/aBER0724/herdr-git-changes/blob/7a164bf9c20555a105c0df0a6841b4608ccdd237/mods/git-changes/diff.js#L80-L147).

Most extra controls are source-control writes (stage, commit, stash, push, pull). They do not belong in Juhas merely to match a larger feature count.

### Better Changes

Implemented strengths include one reusable diff tab, saved per-space selection, monotonically increasing diff request tokens and explicit handling when a selected file no longer has changes. An ordinary successful diff reload does not clear rows first; a changed selection or failed read can clear them. It is a useful stale-response reference, but not a stronger invariant than Juhas's planned atomic candidate publication. [Retained selection](https://github.com/munza/herdr-mods/blob/4e779805efa5e0f5b0d74215ccd6b6e1ea62ac46/better-changes/mods/better-changes/main.js#L120-L147), [diff token and unavailable path](https://github.com/munza/herdr-mods/blob/4e779805efa5e0f5b0d74215ccd6b6e1ea62ac46/better-changes/mods/better-changes/main.js#L432-L535).

Its 300-ms context loop is distinct from Git status polling, which runs every 10 seconds; there is a local watcher and remote polling fallback. Refresh fetches root, status, HEAD, two numstats and optionally the origin URL. Separate sidebar and diff copies each own local state; no cross-copy Git query coordinator is shown. Commit metadata asks twice (`--numstat` and `--name-status`); Juhas already does better with `--raw --numstat`. [Polling](https://github.com/munza/herdr-mods/blob/4e779805efa5e0f5b0d74215ccd6b6e1ea62ac46/better-changes/mods/better-changes/main.js#L149-L175), [refresh](https://github.com/munza/herdr-mods/blob/4e779805efa5e0f5b0d74215ccd6b6e1ea62ac46/better-changes/mods/better-changes/main.js#L224-L311), [two commit reads](https://github.com/munza/herdr-mods/blob/4e779805efa5e0f5b0d74215ccd6b6e1ea62ac46/better-changes/mods/better-changes/main.js#L778-L805).

### WASM diff

This is the strongest additional performance architecture reference, though it is a different runtime and not a drop-in native JavaScript component. Implemented mechanisms:

- Pinned commit sources never poll; mutable/branch sources poll every four seconds only when `input.focused`, ready and with no running commands. This is focus gating, not evidence of all the required Juhas visible-pane semantics. [Poll](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L841-L870).
- The selected path persists across commit navigation and file-list refresh; generations reject old results and limit concurrent requests to four. On missing paths it chooses the first file, which differs from Juhas's proposed explicit missing-file state. [Navigation](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L488-L498), [publication and selection](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L1047-L1068).
- It prioritizes the selected file and files near the viewport. It then asks once for the whole diff if aggregate added+removed rows are at most 200,000. Complete file parts populate the cache, and queued single-file queries already satisfied by that batch are removed. Above the threshold it stays with per-file reads. This is adaptive batching, not proof that fetching every file is always faster. [Batch/cache logic](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L1071-L1183).
- Syntax highlighting runs first on visible hunks, then incrementally in byte-budgeted blocks; parsed tokens are reusable across theme changes. Long/minified lines fall back to plain text. [Budgets](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L54-L78), [highlight blocks](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/highlight.rs#L1-L98).
- Inline changed-word emphasis is implemented locally by comparing paired old/new lines' common prefixes/suffixes and widening the changed segment to word boundaries. It needs no `git --word-diff` subprocess, and keeps source lines intact. It is a heuristic, not a full minimum-edit token diff. [Word emphasis](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/rows.rs#L74-L125).

Important correctness caveat: non-forced refresh keeps cached patches unless a stamp of resolved range, name-status, numstat and untracked names changes. For a working file edited again with identical added/deleted line counts, those metadata can remain identical, leaving its previous patch cached. This is an inference directly from the invalidation condition, not a runtime reproduction. Do not copy this as a content-correct mutable fingerprint; the new Juhas design correctly requires dirty-to-dirty content tests. [Exact stamp/invalidation](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L1021-L1062).

Also, untracked files are listed but their diffs intentionally unavailable under its host capabilities; its whole-branch base discovery targets origin/HEAD/main/master, not user capture rules. These are regressions for Juhas's workflow if copied. [Untracked boundary](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/lib.rs#L20-L24), [source/base model](https://github.com/Calonca/herdr-wasm-mods/blob/007fbb83551810bbc0bf65ec6bc6a3f58d8ea401/modules/diff/src/git.rs#L11-L24).

### Recommended additions to Juhas consideration list

High-value candidates beyond the already accepted plan: (1) syntax coloring with a bounded reusable token cache, (2) inline changed-word emphasis without extra Git commands, (3) direct search in the loaded diff with next/previous match, (4) optional wrapping of long lines, preserving old/new source anchors. Keep full-content copies available separately from painted tokens. These improve human review rather than add repository administration.

Medium-priority experiments: optional all-files multibuffer and bounded neighboring-file prefetch/batched diff reads. Both should be off the critical path of first useful selected diff and limited by total bytes/rows. Measure real multi-file review before promising a speedup; a large eager diff can increase work.

Do not copy: polling hidden copies; reloading immutable commits on each tick; signature/status-only mutable cache invalidation; silently selecting the first file when the old file disappears; separate duplicate copies performing the same Git work; extra staging/pushing/rebasing controls.

### hq-deck (additional direct review comparator)

Pinned `Snarap1/hq-deck` at `542b1463f6204b51cec524ea161f7188ecd68115`. This is a Rust terminal TUI launched by a small Herdr integration, not a native GPUI panel. README requirements explicitly say Linux; it was not built or run on this Windows host. [Integration](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/integrations/herdr/RECIPE.md#L1-L33), [requirements](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/README.md#L33-L43).

Its concrete refresh continuity architecture is especially relevant to the new Juhas design: world-building runs independently of the UI model, worker requests coalesce into the latest input, and completion carries input/generation tags. Reconciliation keeps the cursor by target identity, preserves file-list scroll on polls, and freezes the underlying diff during a modal comment editor or view-anchored drag; it reconciles after the gesture. Selection is cleared when its actual text changed, including same-length edits. These are implemented mechanics, not merely README promises. [World input and builder boundary](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/world.rs#L1-L43), [coalescing worker](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/world.rs#L239-L294), [reconciliation](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/app.rs#L1426-L1510).

The rendering cache keys old/new content hashes (and rename source path), so its cache does not use file-stat counts as a content identity. This is a better correctness example than WASM diff's mutable stamp, though obtaining content still has its own I/O costs. [Content cache](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/diff.rs#L491-L556).

A feature the current Juhas design does not include: a **last-turn baseline can capture an uncommitted worktree**, using a temporary index and Git tree object (staged, unstaged and untracked alike), then a worktree-private ref. Juhas currently offers checkpoints only for committed targets. This could help successive agent rounds with no commits, but is a separate opt-in feature: it writes Git objects/private refs, unlike ordinary read-only review, and should not be slipped into periodic polling. [Snapshot implementation](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/git/scope.rs#L928-L987), [Mark action](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/app.rs#L1829-L1845).

It supports syntax coloring, local word-level emphasis, find-in-file and next/previous comment navigation, useful additions to the human review experience. Its comment model is session-memory-only; closing the pane loses comments. Juhas's durable drafts should be retained as a strength, not replaced by that lifecycle. [Diff emphasis model](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/diff.rs#L20-L78), [comment persistence boundary](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/src/model.rs#L1-L4), [documented keyboard controls](https://github.com/Snarap1/hq-deck/blob/542b1463f6204b51cec524ea161f7188ecd68115/README.md#L115-L139).

## Other source-backed ideas and lifecycle references

### Walkthrough: content-aware progress and optional guided reading

Pinned [dmazlum/herdr-walkthrough](https://github.com/dmazlum/herdr-walkthrough/tree/5c75c3c4ff2933b324c1e3a2a308d0b5a4feb8cb). It groups related edits into model-generated reading steps rather than judging the code. This is adjacent to Juhas, not a replacement for ordinary review. Generated explanations introduce an agent/model dependency; there is no reason to add an automatic model call to Juhas merely to match this capability.

Its useful deterministic part is progress: hunk IDs hash content and trailing function context, excluding hunk line numbers, so adding lines above a hunk does not by itself make it unread. Read state is per repository/path/content, pruned and merged with changes from other windows. Re-generation can identify changed-since-read steps. This strengthens the planned Reviewed/next-unreviewed behavior; Juhas must still distinguish full source identity from progress equivalence, account for repeated hunks and preserve exact comment anchors. Sources: [hunk identity](https://github.com/dmazlum/herdr-walkthrough/blob/5c75c3c4ff2933b324c1e3a2a308d0b5a4feb8cb/mods/walkthrough/lib/hunks.js#L1-L12), [read state](https://github.com/dmazlum/herdr-walkthrough/blob/5c75c3c4ff2933b324c1e3a2a308d0b5a4feb8cb/mods/walkthrough/lib/read.js#L1-L82), [content-dependent cache](https://github.com/dmazlum/herdr-walkthrough/blob/5c75c3c4ff2933b324c1e3a2a308d0b5a4feb8cb/mods/walkthrough/lib/cache.js#L1-L23).

Its small tokenizer guarantees that token text joins back to the original line; a wrong language guess changes color, not text. That invariant is useful if a custom fallback is needed after evaluating native rendering. The heuristic is line-local, not a full language parser. [Tokenizer](https://github.com/dmazlum/herdr-walkthrough/blob/5c75c3c4ff2933b324c1e3a2a308d0b5a4feb8cb/mods/walkthrough/lib/highlight.js#L1-L84).

### Plannotator: a review-level comment and fingerprinted Viewed state

Pinned [iuliansafta/herdr-plannotator](https://github.com/iuliansafta/herdr-plannotator/tree/6a32be132e09ee966de07ff34628062be1e35637). The native pane is a frontend for an existing Plannotator session/server; it should not be mistaken for an independent one-process Git reader. General feedback is a concrete Juhas usability gap: `inputs.note` exists internally, but current rendered controls do not expose it, and `buildBatch` rejects a review without saved file/line drafts. Editing a generated message is already supported, but that does not let a person start a general-only review. ## Consolidated recommendations after the catalog pass

The existing stable-refresh/Git-efficiency design remains the main work. The catalog pass supports it; it does not justify replacing it with periodic full refresh or broad Git administration. The table records the research priorities; the user's subsequent decision accepts the useful candidates as staged design scope except for two-way threads. These are not claims that the functionality was implemented.

| Candidate | Priority | Proposed treatment |
|---|---|---|
| Content-correct cache, stable selected source/path, coalesced worker results, visible-only scheduling | Existing main priority | Implement the accepted contract; use hq-deck and Spend as partial source references |
| Syntax-aware coloring in the main inline-comment diff | High-value rendering candidate | First assess native GPUI support; add bounded reusable tokens only if needed; do not confuse it with whole-line diff colors or Select / copy |
| Emphasis on changed portions of a line | High-value candidate | Local old/new text comparison, no additional Git process; preserve raw source/copy data |
| Find in loaded diff and next/previous match | High-value candidate | Separate from history search; operate on loaded source and explicitly state partial-context boundaries |
| General review comment, including general-only review | High-value candidate | Persist with the repository/review context, no artificial file anchor |
| Viewed / changed since viewed / next unviewed | Already planned | Validate content/mode/rename semantics; use content equivalence for progress without weakening comment provenance |
| Next/previous comment navigation | Small later usability candidate | Jump to the exact saved source or report outdated/unavailable; do not guess line relocation |
| Optional long-line wrapping | Usability candidate requiring layout spike | Current virtual rows have fixed heights; wrapping must use supported native/variable-row behavior without breaking click anchors, split alignment or scroll |
| Two-way threads and agent replies | Excluded by the user | Retain only as a source comparison; no agent reply/resolve protocol in Juhas |
| Uncommitted checkpoint / last-turn baseline | Separate later feature | Explicit capture only, documented Git-object/private-ref writes, ownership and cleanup; never a polling side effect |
| Adaptive batching / bounded next-file prefetch | Performance experiment | Measure representative multi-file review; preserve lazy first useful diff and output/cache limits |
| All-files multibuffer | Optional later review mode | Adds navigation/render/anchor complexity; evaluate after faster one-file review, not as a replacement |
| Guided model-generated reading / requirement mapping | Optional integration, low priority for core | Adds model invocation and transcript/task inputs; no automatic extra agent call in ordinary review |
| PR platform hubs, source-control writes, multi-agent dashboard, document approval | Keep out of the focused core | Existing adjacent mods already serve these workflows |

The user's selected scope is now recorded in the linked design: finish Git/refresh/modes/progress first, then stage general comments and reading improvements, explicit uncommitted snapshots and optional multibuffer/prefetch/guided reading. Treat syntax as a native-component assessment before implementation. Two-way threads are explicitly excluded. No benchmark ranking is claimed, no remote code was executed, and no user's installed mod/configuration was changed during this research.
