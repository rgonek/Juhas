# Compatibility

Supported minimum: Herdr App 0.1.11; native verification is on Windows; runtime JavaScript with gpui-kit, gpui-base and herdr APIs. No Node or browser runtime is needed by the mod. Node >=22 and Git are used by the test suite.

The isolated native spike rendered two copies of a 3,000-row virtual list and a shared selection in a sidebar and full work-area stack. `layout.select {stack,child}` selects the review card or terminal without ending the terminal. This meets the full-card requirement without a Herdr source change. A custom mod draws the card tabs: the installed documentation's shorthand `header: "tabs"` is rejected by this version's parser and is not used.

Core tests execute against real temporary Git repositories. Native UI verification is recorded separately in acceptance.md. Linux/macOS support is designed through platform adapters; a local Windows result does not assert native verification on those systems. Remote SSH is outside initial acceptance.

Platform-specific commands are selected by repository path: Windows directory discovery and working snapshots use PowerShell; POSIX discovery uses `find`, and snapshots use `sh` with a temporary index. The mod does not require PowerShell on Linux or macOS. Git and `hc` calls use argument arrays and explicit working directories. Install with `node scripts/install.mjs` on any of the three systems; `scripts/install.sh` is the POSIX wrapper. Tests cover snapshot races in both shell implementations and directory discovery with spaces, Unicode and pattern characters. CI runs the core suite on Windows, Ubuntu and macOS; it does not validate painted native UI or an agent's response to a delivered review.

The app's generated API files are the version-specific reference. Run `herdr-app check <mod-directory>` after installation and inspect the running UI: check alone does not execute virtual rows or asynchronous states.

Resizable panes use native `h_resizable`, `v_resizable` and `resizable_panel`. The installed runtime must expose these APIs. Virtual lists expose a single click key without mouse modifiers, so range selection uses explicit endpoints and split-diff comments have an explicit old/new side selector. No global modifier tracking or pointer interception is used.

The review UI uses the installed gpui-base `Button`, `Checkbox`, `Toggle` and `Popover` primitives. A small shared theme adapter provides their presentation, as these primitives are unstyled. Native popovers host the existing virtualized branch and recipient lists. The installed Select binding requires consumer-owned option navigation, so it is not substituted for a complete selector. Toolbar selections are groups of native Buttons, including comparison modes, graph filters, diff modes and comment side; the mod uses no Tabs/Tab controls. Inputs, editable review text, resizable groups, scrollbars and virtual lists continue to use native components. A ready-made Tree/Diff binding is not present in the installed JavaScript API.

Diff change navigation uses `VirtualListScrollHandle.new()` in view initialization, `track_scroll` on the active virtual list and `scroll_to_item` from toolbar/command events. The handle is released on view close. The Rust Diff component and its measured annotations are not bound in this installed JavaScript runtime. There is no complete split-view API with independent source viewports and synchronized vertical alignment. Juhas uses bounded native-layout comment cards with a scrolling text body and retains its single diff scroll surface, without per-row event-handler or wheel synchronization workarounds.

The primary UI exposes Commit, All changes and Uncommitted while reusing commit/branch/range/since-review/working-tree scopes. Manual baselines use exclusive ranges; the advanced inclusive range remains supported. History exclusions are resolved OIDs and stay pinned during pagination. Session schema remains version 1: optional branch metadata on new checkpoints and mutable-source fingerprint metadata on new comments are additive. Legacy checkpoints still resolve by explicit ID but are not automatically assigned to an unknown branch. Saved selections gain optional baseline fields; old selections remain readable. Other-view comments retain their original anchors and are validated against source ancestry/fingerprints, independently of inline visibility.

The inline editor is one retained nested View, created with cx.new during initialization and released with its parent. Virtual rows only embed that entity; they do not create state or handlers. The native Textarea state is retained across add/edit, scrolling and navigation. Comment row extents follow explicit line count within a fixed bound; soft-wrapped overflow scrolls inside the card, without synthetic text measurement. Line-height lengths use explicit px strings because this runtime treats bare numbers as multipliers. Missing-source editing uses the same component in a clearly labeled fallback, retaining the original anchor.

Sidebar and expanded copies hand off a bounded in-memory snapshot of loaded history, files, details and diff. The cache is scoped to the project/session, current selection version and configuration; each controller gets a separate copy. It contains no native handles or controller callbacks and does not persist patches to shared storage. Refresh discards it. An evicted or unavailable snapshot falls back to normal Git loading.

History loading uses a standard Lucide loader-circle SVG with native .spin(900); no JavaScript animation timer is used. Controller history notifications request redraws at start/end, including error paths; stale requests cannot clear a newer loading indicator. History/Files share 29 px rows, and graph geometry spans the full row.


Expand now opens/reuses a dedicated review tab keyed by machine, exact repository/worktree root and space. Its repository stays pinned while the source terminal changes directory. A terminal in another project may supply the review source, with an explicitly chosen live agent as recipient. The source context remains separate from the display tab. Old layout-stack helpers remain compatible with existing sidebar layouts.

The new reading view uses measured native `list` rows when wrapping and fixed virtual extents otherwise. Rich spans provide bounded lexical highlighting and local changed-fragment emphasis; this is not a newly exposed Rust Diff binding. Automated rendering harnesses verify callbacks and source identities. Painted wrapping, hit coordinates and scroll-to-item behavior in measured rows still require native acceptance. Opening a new review tab transfers source selection and loaded data; a pixel-exact viewport handoff is not implemented.
